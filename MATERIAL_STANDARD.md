# Стандарт учебных материалов проекта

**Версия стандарта:** 1.0  
**Статус:** рабочий норматив проекта  
**Главный принцип:** **«Понять, увидев в действии.»**

Этот документ задаёт обязательные требования к новым учебным страницам проекта: лабораторным работам, математическим темам, недельным материалам, тренажёрам, разборам домашних заданий и интерактивным инструментам.

Стандарт получен из практики разработки страницы лабораторной работы 1.1.4 и применяется ко всем следующим материалам.

---

## 1. Цель материала

Страница считается удачной не тогда, когда на ней «есть теория и задачи», а тогда, когда студент после прохождения материала может:

1. объяснить своими словами, что означают основные понятия и обозначения;
2. увидеть, как формула или закон работает на конкретном примере;
3. самостоятельно выбрать нужный метод для похожей задачи;
4. выполнить вычисления и проверить результат;
5. понимать, где заканчивается содержание учебного источника и начинается дополнительное пояснение;
6. вернуться к странице после занятия или лабораторной и восстановить ход работы без доступа к преподавателю или штатной программе.

Материал не должен превращаться ни в краткий конспект, ни в цифровую копию учебника. Его задача — сделать исходный учебный материал понятным и действующим.

---

## 2. Источники: обязательная иерархия

### 2.1. Источник истины

Для каждого материала заранее фиксируется набор разрешённых источников. Содержание страницы обязано следовать им.

Приоритет по умолчанию:

1. **программа курса / план недели** — определяет, что именно сейчас изучается и какие задачи заданы;
2. **актуальная методичка или основной учебник курса** — определяет обозначения, формулы, определения, порядок изложения и принятые соглашения;
3. **загруженный задачник** — используется для точного условия домашней задачи и её нумерации;
4. **книга с решениями** — используется для внутренней проверки метода и ответа, но не для преждевременной выдачи готового решения;
5. **другие предоставленные пользователем учебные материалы** — только как дополнительный источник, если они не меняют содержание основного;
6. **внешние источники** — не используются для учебного содержания без прямого запроса пользователя.

Если программа ссылается на более новое издание, которого в проекте нет, нумерация доступного издания считается рабочей до первого обнаруженного расхождения.

### 2.2. Нельзя «исправлять» источник молча

Если в источнике используется определённое соглашение, страница использует именно его.

Примеры:

- если дисперсия в методичке определена с делением на `N`, страница не заменяет её на вариант с `N - 1`;
- если в задачнике используются конкретные обозначения, они сохраняются;
- если точная параметризация программного генератора не описана, страница не придумывает её;
- если два места источника противоречат друг другу, это отмечается явно, а не скрывается.

### 2.3. Трассируемость

На странице должен быть видимый блок **«Источники»**, где указано:

- название книги / методички;
- издание или версия, если известно;
- используемые главы, параграфы или страницы;
- роль источника: теория, условия задач, программа работы и т. п.

Для больших материалов желательно указывать источник рядом с раскрывающимся теоретическим блоком.

---

## 3. Главный методический принцип: «Понять, увидев в действии»

Каждая центральная идея страницы должна иметь не только текстовое объяснение, но и **действие**, которое показывает смысл идеи.

Под действием понимается одно из следующего:

- интерактивная визуализация;
- изменение параметра с немедленным изменением результата;
- пошаговое построение формулы;
- выделение частей объекта при наведении или клике;
- проигрывание процесса во времени;
- работа с собственными данными пользователя;
- тренажёр, в котором студент сам делает ключевой шаг;
- сравнение двух случаев с мгновенной обратной связью.

Интерактивность не должна быть декоративной. Если элемент можно удалить без потери понимания, он не является достаточным учебным интерактивом.

## 4. Обязательная архитектура страницы

Конкретная композиция может различаться, но полноценный материал должен содержать следующие уровни.

### 4.1. Вход

В верхней части студент сразу видит:

- что это за тема / неделя / лабораторная;
- чему он научится;
- какие источники используются;
- быстрый маршрут по странице;
- несколько входов: например «начать с нуля», «перейти к задаче», «у меня уже есть данные».

### 4.2. Теория с нуля

Страница не предполагает автоматически, что первокурсник знает университетские определения.

Если появляется новое обозначение — например `det A`, `Σ`, `∈`, `∀`, `σ`, `dx`, `||v||` — нужно объяснить:

1. как оно читается;
2. что означает;
3. что означает именно в этой теме;
4. как используется в следующем действии или задаче.

Теория строится слоями:

- **быстрый слой** — краткое объяснение для повторения;
- **подробный слой** — раскрывающиеся блоки вплоть до полного необходимого объёма источника;
- **действие** — интерактив, где понятие можно увидеть.

Большие теоретические блоки по умолчанию могут быть свёрнуты, чтобы не мешать студенту, который уже знает тему.

### 4.3. Основной интерактив

У каждой страницы должна быть хотя бы одна центральная интерактивная модель, связанная с главным понятием.

Примеры:

- матрица: клик по элементу результата подсвечивает соответствующие строку и столбец сомножителей;
- производная: движение точки показывает секущую, переходящую в касательную;
- лабораторная статистика: накопление отсчётов одновременно меняет среднее, гистограмму и ошибку;
- геометрия: изменение коэффициентов уравнения сразу двигает объект.

### 4.4. Практика

После объяснения студент должен выполнить содержательный шаг сам.

Практика строится лестницей:

1. наводящий вопрос;
2. выбор идеи или формулы;
3. один промежуточный шаг;
4. почти полное решение;
5. полное решение — только после явного раскрытия.

Для домашней задачи по умолчанию нельзя показывать полный ответ сразу.

### 4.5. Самопроверка

В конце темы нужен тренажёр, а не просто список ответов.

Минимальные требования:

- банк вопросов больше одного короткого прохода;
- случайная выборка или режим «все вопросы»;
- обратная связь после ответа;
- объяснение, почему ответ правильный;
- вопросы не только на формулы, но и на смысл, выбор метода и типичные ошибки.

### 4.6. «Сделай сам без сайта»

Если материал использует автоматический инструмент, в конце должен быть путь к самостоятельному выполнению того же действия без него.

Примеры:

- построить графики вручную в Calc / Excel / Python;
- решить систему на бумаге после работы с интерактивным Крамером;
- вручную составить таблицу измерений;
- самому построить схему или доказательство.

Цель — не сделать студента зависимым от сайта.

## 5. Требования к математическим страницам

### 5.1. Смысл операции раньше автоматизма

Перед серией вычислений студент должен увидеть, что операция делает.

Например, для произведения матриц недостаточно дать формулу `c_ij = Σ a_ik b_kj`. Нужно интерактивно связать:

- `i` с выбранной строкой первой матрицы;
- `j` с выбранным столбцом второй;
- каждый множитель в сумме с конкретной парой элементов.

### 5.2. Обозначения не считаются очевидными

Новые индексы, греческие буквы и сокращения получают локальное объяснение.

### 5.3. Доказательства

Если цель страницы — научить доказательству, оно строится как маршрут:

- что надо доказать;
- из какого определения начать;
- какая конструкция нужна;
- какие равенства являются ключевыми;
- полный текст доказательства скрыт до запроса.

### 5.4. Домашняя работа

Условие берётся только из задачника или другого предоставленного источника. Нельзя восстанавливать условие «по памяти».

Для каждой задачи полезны:

- тип задачи;
- что в условии является сигналом к выбору метода;
- первая подсказка;
- типичная ошибка;
- проверка ответа;
- полный разбор в скрытом блоке, если он нужен странице.

Если точное условие в текущем наборе материалов недоступно, это явно отмечается; вместо него можно дать **аналогичный тренировочный пример**, но не выдавать его за домашнюю задачу.

---

## 6. Требования к физике и лабораторным

Перед вычислениями страница должна помогать построить физическую модель:

- что является системой;
- что измеряется;
- какая система отсчёта используется;
- какие силы или процессы существенны;
- какие величины известны;
- какой закон связывает их.

Для лабораторной страницы дополнительно обязательны:

1. цель работы и оборудование;
2. теория установки вплоть до уровня методички;
3. последовательность действий на установке;
4. формат сырых данных;
5. обработка своих данных;
6. проверка размерностей и единиц;
7. интерактивная версия ключевых графиков / процессов;
8. маркировка реконструированных элементов как примерной версии, если исходное ПО не воспроизводится точно;
9. самостоятельное воспроизведение обработки без сайта.

---

## 7. Интерактивные элементы: требования качества

Каждый интерактив должен отвечать на три вопроса:

1. **Что я могу изменить?**
2. **Что изменится в ответ?**
3. **Какой вывод я должен из этого сделать?**

Обязательные свойства:

- реакция на действие мгновенная и понятная;
- текущее состояние видно;
- есть способ сбросить пример;
- случайные данные явно помечены как учебные / синтетические;
- критические действия не происходят случайным кликом;
- после паузы процесс можно продолжить, если пользователь ожидает именно паузу;
- интерфейс не маскирует неизвестные детали источника выдуманными значениями.

---

## 8. Стиль объяснения

Текст должен быть рассчитан на первокурсника, который знает школьную математику, но может не знать университетской терминологии.

Предпочтительный порядок:

**наблюдение → вопрос → определение / формула → действие → вывод.**

Не использовать без необходимости:

- длинные академические вводные;
- определения, которые никак не применяются дальше;
- декоративный формализм;
- фразы о внутренних ограничениях разработки вроде «нам не удалось восстановить…», если достаточно нейтрально сказать «это примерная версия».

Тон страницы — нормальный учебный, без инфантилизации.

---

## 9. Визуальный стандарт

Страница должна визуально совпадать с проектом, но не обязана быть копией страницы 1.1.4.

Общие требования:

- единая шапка проекта;
- светлый нейтральный фон;
- ограниченная палитра с одним основным акцентом;
- большие заголовки и ясная визуальная иерархия;
- интерактивы размещаются рядом с объясняемой идеей;
- раскрывающиеся блоки стилизованы и не выглядят как браузерный HTML по умолчанию;
- не должно быть «стен» из десятков одинаковых карточек без навигации;
- мобильная версия остаётся рабочей;
- состояние `hover` не является единственным способом получить важную информацию.

---

## 10. Технический стандарт

Проект остаётся полностью статическим:

- HTML;
- CSS;
- vanilla JavaScript;
- GitHub Pages;
- без обязательного backend;
- без секретов и токенов в репозитории.

Допустимо:

- `localStorage` для локального прогресса и настроек;
- статические JSON-файлы;
- чтение локально выбранных пользователем файлов в браузере;
- клиентские вычисления и графики.

### 10.1. Имена ресурсов

Файлы интерфейса должны иметь стабильные имена (`app.js`, `styles.css`). Для сброса кэша используется query string версии: `app.js?v=0.15`.

Не создавать `app-0.15.js`, `app-0.16.js` и т. п. без необходимости.

### 10.2. Ошибки

Пользовательская ошибка объясняется человеческим языком. Технические детали можно показывать вторым уровнем.

### 10.3. Проверки перед релизом

Минимум:

- `node --check` для JavaScript;
- проверка локальных `href/src`;
- отсутствие ссылок на несуществующие якоря;
- проверка основных интерактивов вручную;
- проверка мобильной ширины;
- проверка отсутствия устаревших файлов, которые не заменяются при ручной загрузке в GitHub.

---

## 11. Работа с расхождениями и неопределённостью

Если источник содержит расхождение:

1. не скрывать его;
2. указать оба места;
3. выбрать рабочее правило только на основании более фундаментальной формулы или явной инструкции источника;
4. пометить выбор на странице.

Если деталь неизвестна:

- не придумывать её;
- сформулировать интерфейс нейтрально;
- при необходимости написать «примерная версия», «учебная модель», «один из возможных способов».

---

## 12. Что считается запрещённым качественно

Страница не проходит стандарт, если она:

- представляет собой длинный текст без действия;
- содержит красивые, но бесполезные интерактивы;
- использует формулы или определения из случайных внешних источников вместо материалов курса;
- меняет обозначения без необходимости;
- выдаёт реконструкцию за точную копию;
- автоматически решает домашнюю задачу без обучения методу;
- прячет важную теорию настолько глубоко, что её невозможно обнаружить;
- показывает ответ, но не даёт способа проверить знаки, арифметику, единицы или смысл результата;
- требует сайта для действия, которое студент должен уметь выполнять самостоятельно.

## 13. Минимальный шаблон нового материала

```text
Название темы / недели
│
├── Что научимся делать
├── Источники
├── Маршрут
│
├── Теория с нуля
│   ├── быстрый уровень
│   └── подробные раскрывающиеся блоки
│
├── Главный интерактив: «увидеть в действии»
├── Вторичные интерактивы / сравнения
│
├── Разбор типовых задач
├── Домашняя работа с лестницей подсказок
│
├── Инструмент проверки своих вычислений
├── Самопроверка
│
└── Сделай то же самое самостоятельно без сайта
```

Не каждый материал обязан иметь одинаковое число секций, но все функции этого шаблона должны быть либо реализованы, либо осознанно признаны неприменимыми.

## 14. Quality Gate перед публикацией

Материал можно считать кандидатом на эталон, если на все вопросы ниже можно ответить «да».

### Содержание

- [ ] Явно указаны разрешённые источники.
- [ ] Все основные формулы и соглашения совпадают с ними.
- [ ] Условия домашних задач не придуманы по памяти.
- [ ] Расхождения источников отмечены.
- [ ] Новые обозначения объяснены.

### Понимание

- [ ] Центральную идею можно увидеть в действии.
- [ ] Есть путь для человека, который начинает почти с нуля.
- [ ] Есть быстрый путь для повторения.
- [ ] После интерактива сформулирован учебный вывод.

### Практика

- [ ] Есть самостоятельный содержательный шаг.
- [ ] Домашняя работа не раскрывается полностью сразу.
- [ ] Есть проверка арифметики / знаков / единиц / смысла.
- [ ] Есть расширенная самопроверка.
- [ ] Есть инструкция, как выполнить ключевую работу без сайта.

### Интерфейс

- [ ] Нет браузерных `details/button` без стилизации.
- [ ] Кнопки ведут себя предсказуемо.
- [ ] Пауза продолжает, сброс сбрасывает.
- [ ] Страница читаема на телефоне.
- [ ] Навигация не перегружена.

### Техника

- [ ] JavaScript проходит синтаксическую проверку.
- [ ] Нет битых локальных ссылок.
- [ ] Версия ресурсов обновлена через query string.
- [ ] Страница работает на статическом GitHub Pages.

## 15. Эталон проекта

До появления более нового утверждённого материала эталонным примером применения этого стандарта считается финальная линия страницы **физической лабораторной работы 1.1.4**.

Новые страницы не должны слепо копировать её структуру. Они должны воспроизводить её уровень:

- верность источнику;
- глубину теории;
- полезность интерактивов;
- возможность пройти материал с нуля;
- самостоятельную практику;
- техническую аккуратность.
